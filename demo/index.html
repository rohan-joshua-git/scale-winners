      How TrustSphere works

      Eight phases, one auditable path from raw ledger to a human decision.

      Every driver traces back to a source row, and every severity is policy-set — nothing here is fitted against outcomes, and nothing decides without an analyst signing off.

      1. 1
        HANA Cloud

        Ingestion

        16 tables — transactions, companies, beneficial owners, risk scores, alerts, cases — pulled from the real TEAM_07 schema. Seed data from the case organizers, not synthetic, landing in a local cache.

      2. 2

        Evidence pack

        Pushed-down SQL assembles one provenance-carrying record per alert. Every join is a LEFT JOIN, so a missing dimension row never silently drops an alert from the queue.

      3. 3
        31 policy-set rules

        Risk drivers

        Each rule's severity is set by policy, never fitted against outcomes — that keeps this rule-based prioritisation, not a model influencing customer decisions. Drivers decompose the existing risk score and report how often each rule fires, so an investigator can calibrate.

      4. 4

        Backlog ranking

        The unresolved queue is ranked by regulatory consequence of leaving an alert unresolved — deterministic, policy-weighted, stress-tested. It ranks exposure, not the odds an alert resolves as a true positive.

      5. 5
        SAP AI Core

        GraphRAG ingestion

        FATF, OFAC, EU AML, Wolfsberg, and MAS text is chunked, embedded, and LLM-extracted into a regulatory graph in HANA; a separate deterministic pass adds clients, beneficial owners, and alerts from the same source tables.

      6. 6

        GraphRAG retrieval

        Native HANA vector search over regulatory text runs alongside degree-capped graph traversal, surfacing both the clause behind a flag and the connected entities — shared owners, prior alerts — vector search alone can't reach.

      7. 7
        FastAPI

        Grounding API

        POST /ground-risk-driver wires retrieval up for anything downstream that needs it, returning vector matches and graph context together, ranked and capped for readability.

      8. 8

        Narrative & human review

        Structured drivers become prose by template, not by a model paraphrasing freely — every number is checked against its source field first. An analyst reads it and is the one who accepts or overrides the tier.

      Beneficial-ownership graph

      Unstructured records. One traceable structure.

      On their own, four company registrations and a wire transfer look unrelated. Graph traversal over beneficial-ownership records resolves them into a single structure in seconds.

      Beneficial-ownership graph traversal links the beneficiary to 3 other shell entities registered within 11 days of each other, all controlled by a single ultimate beneficial owner.

      Phase 4e — Typology & severity matrix

      Likelihood and severity, not one score, decide the tier.

      Two independent bands look up a tier in a fixed matrix — transparent and auditable, not a black-box threshold. Sanctions hits bypass it entirely via a hard override straight to Critical.
